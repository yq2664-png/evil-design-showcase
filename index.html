了解实验方法与标签说明

同一题目分别交给 GPT、DeepSeek、Xiaomi MiMo 独立生成；GPT 对照三份候选，列出其他两个候选相对 GPT 的具体弱点；GPT 提出的弱点未经单独证据核验，直接交给 DeepSeek 尝试移植到 GPT 原稿。完整页面区的 Before 是 GPT 原稿，After 是先移植弱点、再迁移 DS 或 MiMo 的中性风格。下方三图仅展示三家独立原答各自第一屏。风格差异本身不代表质量高低。GPT 的评价是模型假设，不代表真实质量标签；所有样本仍为 expected-unverified。本版沿用已保存的三模型候选、GPT 评价和缺点移植结果，在 After 上增加每组不同的多维变化并重新验证。独立候选截图已等待显现动画；GPT 原评价使用旧截图，需复核。此公开展示不包含内部评价记录。

Landing Page

按顺序浏览独立答案、问题清单和 Before / After 对照。

01 · 三个答案

同一题目由 GPT、DeepSeek、Xiaomi MiMo 独立生成。以下为同一视口的 1920 × 1080 首屏。

02 · 问题清单

GPT 基于现有截图和页面证据提出 8 项候选问题，不设条数上限。这是对独立答案的补充评价；After 沿用先前的移植清单。问题尚未经过人工确认。

  1. I1 · DeepSeek · Visual

    主标题连续四行且占据较大纵向空间，使首屏信息层级过度集中于标题，三项利益点需要继续滚动才能看到。

    查看依据

    截图左侧标题从 Objects that 延伸至 considered.，正文和 CTA 位于其下方；#hero-title 的 font-size 为 100.8px、line-height 为 106.848px，测量高度为 427px。GPT 标题为两行，测量高度为 200px，首屏同时展示三项利益点。

  2. I2 · DeepSeek · Visual

    页头主 CTA 的灰褐色文字与橙色底色区分较弱，也与正文同色 CTA 的白字处理不一致。

    查看依据

    截图右上角 Shop the collection 为橙底灰褐字，左下方同名主 CTA 为橙底白字；前者文字明显较难辨认。没有该按钮的文字及背景计算值，不能据此给出对比度比值或 WCAG 结论。

  3. I3 · DeepSeek · Logic

    Shop the collection 路径在两个推广区之间往返，没有在所提供的完整 HTML 中继续进入商品选择或购物目的地。

    查看依据

    hero 与 #collection 内的同名链接均为 href="#shop"，#shop 内同名链接为 href="#collection"；完整 HTML 中没有进一步的商品操作入口。GPT 的集合区则提供商品信息与 Add to bag 按钮，但其运行行为同样未获验证。

  4. I4 · DeepSeek · Logic

    Delivery & returns 链接目标不提供相应详情，链接名称与目标内容不匹配。

    查看依据

    页脚 Delivery & returns 使用 href="#shop"；#shop 只有 Bring considered objects home.、推广说明和返回 #collection 的 CTA，没有配送或退货详情。

  5. I5 · DeepSeek · Usability

    主要导航未使用导航地标语义，不利于按地标定位主要链接。

    查看依据

    完整 HTML 中页头主要链接使用 div class="wrap nav" 和 ul class="nav-links"，没有 nav 或 role="navigation"；GPT 对应结构为带 aria-label 的 nav。此处仅判断结构缺失，不推断具体屏幕阅读器表现。

  6. I6 · DeepSeek · Usability

    两处 CSS 产品插画使用普通 div 承载 aria-label，却未声明图像角色，缺少明确的命名图像语义。

    查看依据

    div.hero-art 与 div.collection-art 都有插画描述 aria-label，但没有 role="img"，内部绘制元素均设置 aria-hidden="true"。GPT 的对应插画容器明确使用 role="img"。

  7. I7 · Xiaomi MiMo · Visual

    主标题以四行展开，占据较多首屏高度，压缩了正文、行动区和证明信息的纵向空间。

    查看依据

    截图标题依次为 Quiet objects、for a、well-lived、home.，CTA 下方的评论指标已接近首屏底部；#hero-title 的 font-size 为 98.4px，测量高度为 374px。GPT 对应标题为两行、测量高度为 200px。

  8. I8 · Xiaomi MiMo · Visual

    三项同级 hero 指标采用两项在上、一项独占下一行的排列，削弱了并列关系与视觉均衡。

    查看依据

    截图左下方 92% 和 10 yr 位于同一行，4.9/5 单独位于下一行；HTML 中三者均为同一 hero-facts 容器下的 fact。现有表中没有该容器的布局计算样式，无法确定具体 CSS 成因。

03 · Before / After

左侧是 GPT 原稿，右侧是修改后的页面。可在截图内滚动查看完整页面。

查看 After 的变化维度

After 的视觉方向：cool utilitarian retail；变化维度：palette、typography、layout rhythm、CTA affordance、illustration finish。

04 · 缺点总结

补充评价记录 8 项候选问题；当前 After 依据先前提交的 3 项可移植弱点生成，涉及的样式参数：color、padding。

补充问题未自动应用到 After。After 还包含中性的风格变化。模型提出的问题和视觉差异都不能直接证明设计质量下降，仍需人工评价。

Pricing Page

按顺序浏览独立答案、问题清单和 Before / After 对照。

01 · 三个答案

同一题目由 GPT、DeepSeek、Xiaomi MiMo 独立生成。以下为同一视口的 1920 × 1080 首屏。

02 · 问题清单

GPT 基于现有截图和页面证据提出 5 项候选问题，不设条数上限。这是对独立答案的补充评价；After 沿用先前的移植清单。问题尚未经过人工确认。

  1. I1 · DeepSeek · Logic

    全局计费说明称按工作区计价，Team 和 Scale 却按成员计价，用户无法从一致口径判断实际费用。

    查看依据

    截图计费切换下方及 HTML #billing-note 为“per workspace, per month”；Team、Scale 的 price-unit 均为“/ member / month”。

  2. I2 · DeepSeek · Interaction

    Sign in 标签暗示登录，但链接声明的是页内 CTA 跳转，静态操作提示与目标类型不一致。

    查看依据

    页头 HTML：<a class="btn btn-ghost" href="#final-cta">Sign in</a>。此证据仅支持链接声明目标存在歧义，不证明脚本运行后的最终行为。

  3. I3 · Xiaomi MiMo · Visual

    三行大标题与较高头图区延后了核心定价内容，导致桌面首屏无法完整查看价格和方案 CTA。

    查看依据

    截图上部左侧标题占三行，右侧大量留白；底部卡片价格被截断，方案 CTA 不可见。#hero-title 的 font-size 为 69.6px、line-height 为 77.952px，矩形高 234px；#top 高 819px。GPT 截图已展示完整价格和方案 CTA。

  4. I4 · Xiaomi MiMo · Logic

    统一的年度节省 20% 提示与 Starter 所声明的年度价格和节省金额不符。

    查看依据

    HTML 的 #save-tag 为“Annual saves 20%”；Starter 声明 data-monthly="8"、data-annual="6"，data-sub-annual="Billed $72 per user / year. Save $24 per user."。$24 ÷ ($8 × 12) = 25%。

  5. I5 · Xiaomi MiMo · Interaction

    Sign in 标签暗示登录，但链接声明的是页内 CTA 跳转，静态操作提示与目标类型不一致。

    查看依据

    页头 HTML：<a class="btn btn-ghost" href="#cta">Sign in</a>。未提供脚本和目标区完整内容，不能进一步断言实际登录流程失效。

ToB 产品介绍页

按顺序浏览独立答案、问题清单和 Before / After 对照。

01 · 三个答案

同一题目由 GPT、DeepSeek、Xiaomi MiMo 独立生成。以下为同一视口的 1920 × 1080 首屏。

02 · 问题清单

GPT 基于现有截图和页面证据提出 5 项候选问题，不设条数上限。这是对独立答案的补充评价；After 沿用先前的移植清单。问题尚未经过人工确认。

  1. I1 · DeepSeek · Visual

    工作负载图显示了不同百分比，却没有可辨识的对应比例填充，削弱了用图形快速比较各作业区负载的作用。

    查看依据

    首屏右侧 Zone workload 面板中，72%、58%、91%、64% 四个数值对应的条形均呈相同长度的浅灰轨道，未见不同长度的数值填充。此问题依据稳定后的截图，而非推测动画或脚本原因。

  2. I2 · Xiaomi MiMo · Visual

    桌面页头同时显示两个相同目标、相同文案的演示 CTA，形成重复视觉强调并占用导航空间。

    查看依据

    截图顶部 FAQ 后方和最右侧各有一枚橙色 Request a demo。HTML 中，li.mobile-cta 内的链接和 div.nav-cta 内的主链接均为 href="#demo"，且文案相同。GPT 截图的页头仅显示一个演示 CTA。

  3. I3 · Xiaomi MiMo · Visual

    当前桌面页头的导航与操作标签被挤成多处双行，降低了横向扫描的紧凑性；列表内演示按钮的文字还紧贴左边缘。

    查看依据

    1920 × 1080 截图顶部，Why AtlasFlow、How it works、Talk to sales 以及两枚 Request a demo 均分为两行；FAQ 右侧第一枚橙色按钮的文字几乎贴着左侧轮廓。相比之下，GPT 与 DeepSeek 的可见桌面导航标签均为单行。这不是对其他视口表现的判断。

  4. I4 · Xiaomi MiMo · Visual

    页头两枚同文案、同目标的主按钮使用不同文字颜色，使同类主要操作的视觉规则不一致。

    查看依据

    截图顶部 FAQ 后的橙色 Request a demo 使用深色文字，最右侧橙色 Request a demo 使用白色文字。HTML 中两者分别使用 btn btn--primary，且都指向 #demo；英雄区同类橙色主按钮也使用白色文字。这里仅指出一致性问题，不推断其对比度是否达标。

  5. I5 · Xiaomi MiMo · Logic

    异常面板将已自动处理的条目计入“4 OPEN”的可见列表，却没有解释开放项与已解决项的区别，使汇总状态难以与明细核对。

    查看依据

    首屏右侧 Exceptions 面板的角标是 4 OPEN；四条明细中，最后一条为 ASN 8842 — reconciled automatically，并以绿色圆点标识。其他三条分别描述 carrier ETA slipped、pick rate below plan、lines at short-pick risk。
